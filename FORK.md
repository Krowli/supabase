# Studio fork — self-hosted Authentication pages

This is a fork of `supabase/supabase` on branch `fork/auth-selfhosted`. It makes Supabase
Studio's Authentication configuration pages work on a self-hosted stack, where upstream hides
them because there is no hosted control plane to save a setting to.

Everything the fork adds lives under `apps/studio/`, plus this file and
`.github/workflows/studio-fork-publish.yml`.

## What this fork changes

Upstream Studio renders the Authentication settings pages only when `IS_PLATFORM` is true, and
its auth-config query refuses to run otherwise. Self-hosted the menu is down to the Users list
and a link out to database Policies. The fork un-hides those pages and gives them a backend that
writes GoTrue's own configuration files.

**The gate edits** — four small changes, each with a comment on the spot saying why:

| File                                                               | Change                                                                                                                      |
| ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| `apps/studio/data/auth/auth-config-query.ts`                       | Dropped `IS_PLATFORM` from the query's `enabled` condition, so the config is fetched self-hosted.                           |
| `apps/studio/components/layouts/AuthLayout/AuthLayout.utils.ts`    | `useGenerateAuthMenu` passes `isPlatform: true`, and treats passkeys as on unless the platform flag says otherwise.         |
| `apps/studio/components/interfaces/Auth/Hooks/AddHookDropdown.tsx` | Self-hosted, every hook definition counts as entitled. An entitlement is a hosted-plan allowance and there is no plan here. |
| `apps/studio/pages/project/[ref]/auth/passkeys.tsx`                | Same passkey-flag treatment as the menu.                                                                                    |

**New backend** — `apps/studio/lib/api/self-hosted/auth-config/`:

| Module              | Owns                                                                                                            |
| ------------------- | --------------------------------------------------------------------------------------------------------------- |
| `state.ts`          | Studio's record of what the UI changed: `auth-config.json`, written atomically at mode 0600.                    |
| `render.ts`         | Rendering and atomically writing `99_studio.env` into GoTrue's config directory.                                |
| `defaults.ts`       | The value every one of GoTrue's 237 response keys takes when nothing has set it, and the 13 email template ids. |
| `keys.generated.ts` | The 242 platform config keys and their declared types, taken from `packages/api-types`.                         |
| `mapping.ts`        | Platform key → GoTrue env name, including the folded client-id lists and the email-template URLs.               |
| `validate.ts`       | Refusal of any patch the running GoTrue would reject or misread.                                                |
| `index.ts`          | `getAuthConfig`, `updateAuthConfig`, `resetTemplate`, and `MIRRORED_ENV_KEYS`.                                  |

Each module has a `*.test.ts` beside it.

**New API handlers** under `apps/studio/pages/api/platform/auth/[ref]/`, each with a TanStack
mirror at the matching path under `apps/studio/routes/api/platform/auth/$ref/` and a test under
`apps/studio/tests/pages/api/platform/auth/[ref]/`:

| Route                             | Methods                                                    |
| --------------------------------- | ---------------------------------------------------------- |
| `config.ts`                       | `GET` the whole auth config, `PATCH` to change it          |
| `config/hooks.ts`                 | `PATCH`, refusing any key that does not start with `HOOK_` |
| `templates/[template]/content.ts` | `GET` one email template body as HTML                      |
| `templates/[template]/reset.ts`   | `POST` to drop a customised template body and subject      |
| `validate/spam.ts`                | `POST`, always `{ rules: [] }`                             |

**Also modified:** `apps/studio/turbo.jsonc`, which has to name every environment variable the
build reads, and `apps/studio/routeTree.gen.ts`, regenerated by the TanStack generator.

## How it works

Studio keeps its own state file and renders GoTrue's configuration from it. GoTrue is never
read back for the current settings: keys in its config directory are sticky, and its running
config mixes container environment with every file in that directory, so there is nothing there
to read a single setting out of.

1. **A `GET` answers from three sources, in order.** What the UI has saved (`auth-config.json`),
   else the value GoTrue was started with (the `GOTRUE_*` variables named in `MIRRORED_ENV_KEYS`,
   mirrored into Studio's own container), else the recorded GoTrue default.
2. **A `PATCH` validates, records, and re-renders.** The patch is checked against the merged
   config, merged into `auth-config.json`, and the whole managed set is rendered to
   `99_studio.env` in the GoTrue config directory. Both files are written to a temporary name
   and renamed, so a watcher never sees a half-written file.
3. **GoTrue reloads on its own.** Started with `--config-dir /etc/gotrue`, it watches for changes
   to `*.env` files there and reloads after a grace period. The default grace period is 5 s and
   the reload ticker fires at most 1 s apart (`internal/conf/configuration.go:447`,
   `internal/reloader/reloader.go:24`), so a save is live within about 6 seconds.
4. **Config-dir files beat container environment.** GoTrue loads the directory with
   `godotenv.Overload` (`internal/conf/confload/confload.go:79`), which overwrites variables
   already in the environment. Files load in filename order, and `99_studio.env` sorts last.
5. **Email templates are served, not embedded.** GoTrue takes a URL for a template body, never
   the body itself, so `mapping.ts` writes
   `GOTRUE_MAILER_TEMPLATES_<ID>=$STUDIO_INTERNAL_URL/api/platform/auth/default/templates/<id>/content`
   and GoTrue fetches it over the compose network. A template with no custom body is written as
   an empty string, which is how GoTrue is told to go back to its built-in one.

Two rules of GoTrue's own that the renderer is built around:

- **Keys are sticky.** Removing a line from `99_studio.env` does not unset the value; it leaves
  the last one in force. So every managed key that has a value is emitted on every write.
- **An empty value breaks the whole reload** for an int, bool, float or duration field. Only the
  106 keys whose GoTrue field is string-typed are ever written as `KEY=""`; the rest are omitted
  when empty.

### Environment variables Studio reads

| Variable                            | Default                       | Used for                                                                                           |
| ----------------------------------- | ----------------------------- | -------------------------------------------------------------------------------------------------- |
| `GOTRUE_CONFIG_DIR`                 | `/etc/gotrue`                 | Where `99_studio.env` is written                                                                   |
| `STUDIO_AUTH_STATE_DIR`             | `/var/lib/studio`             | Where `auth-config.json` is kept                                                                   |
| `STUDIO_INTERNAL_URL`               | `http://supabase-studio:3000` | The base of the template URLs GoTrue fetches                                                       |
| `SUPABASE_PUBLIC_URL`               | `''`                          | Builds each provider's `GOTRUE_EXTERNAL_<PROVIDER>_REDIRECT_URI`. Unset, no callback is written and whatever the auth container already has stands. Already set by the stock compose |
| the 20 names in `MIRRORED_ENV_KEYS` | —                             | What a `GET` answers with before anything has been saved                                           |

## Coolify compose changes

Edit the Coolify Supabase service's compose file as follows. The two volumes are what carries
Studio's writes to GoTrue.

<!-- prettier-ignore -->
```yaml
volumes:                        # top level, next to the existing named volumes
  gotrue-config:
  studio-auth-state:

services:                       # the compose file's existing services block
  supabase-auth:
    command: ["auth", "--config-dir", "/etc/gotrue"]
    volumes:
      - gotrue-config:/etc/gotrue:ro
    environment:                # add to the existing list
      - GOTRUE_MAILER_TEMPLATE_RELOADING_ENABLED=true
      - GOTRUE_MAILER_TEMPLATE_MAX_AGE=1m

  supabase-studio:
    image: ghcr.io/krowli/studio:<tag>
    volumes:                    # add to the existing list
      - gotrue-config:/etc/gotrue
      - studio-auth-state:/var/lib/studio
    environment:                # add to the existing list
      - STUDIO_INTERNAL_URL=http://supabase-studio:3000
      - GOTRUE_CONFIG_DIR=/etc/gotrue
      - STUDIO_AUTH_STATE_DIR=/var/lib/studio
      - GOTRUE_SITE_URL=${GOTRUE_SITE_URL:-${SERVICE_URL_SUPABASEKONG}}
      - GOTRUE_URI_ALLOW_LIST=${ADDITIONAL_REDIRECT_URLS}
      - GOTRUE_DISABLE_SIGNUP=${DISABLE_SIGNUP:-false}
      - GOTRUE_JWT_EXP=${JWT_EXPIRY:-3600}
      - GOTRUE_EXTERNAL_EMAIL_ENABLED=${ENABLE_EMAIL_SIGNUP:-true}
      - GOTRUE_EXTERNAL_ANONYMOUS_USERS_ENABLED=${ENABLE_ANONYMOUS_USERS:-false}
      - GOTRUE_MAILER_AUTOCONFIRM=${ENABLE_EMAIL_AUTOCONFIRM:-false}
      - GOTRUE_SMTP_ADMIN_EMAIL=${SMTP_ADMIN_EMAIL}
      - GOTRUE_SMTP_HOST=${SMTP_HOST}
      - GOTRUE_SMTP_PORT=${SMTP_PORT:-587}
      - GOTRUE_SMTP_USER=${SMTP_USER}
      - GOTRUE_SMTP_PASS=${SMTP_PASS}
      - GOTRUE_SMTP_SENDER_NAME=${SMTP_SENDER_NAME}
      - GOTRUE_EXTERNAL_PHONE_ENABLED=${ENABLE_PHONE_SIGNUP:-true}
      - GOTRUE_SMS_AUTOCONFIRM=${ENABLE_PHONE_AUTOCONFIRM:-true}
      - GOTRUE_MAILER_SUBJECTS_CONFIRMATION=${MAILER_SUBJECTS_CONFIRMATION}
      - GOTRUE_MAILER_SUBJECTS_RECOVERY=${MAILER_SUBJECTS_RECOVERY}
      - GOTRUE_MAILER_SUBJECTS_MAGIC_LINK=${MAILER_SUBJECTS_MAGIC_LINK}
      - GOTRUE_MAILER_SUBJECTS_EMAIL_CHANGE=${MAILER_SUBJECTS_EMAIL_CHANGE}
      - GOTRUE_MAILER_SUBJECTS_INVITE=${MAILER_SUBJECTS_INVITE}
      - ENABLED_FEATURES_AUTHENTICATION_THIRD_PARTY_AUTH=false
```

The block is written list-style (`- KEY=value`), which is the form the Coolify Supabase template
uses. If the compose you are editing writes `environment:` as a mapping instead, convert these
lines to `KEY: value` form — never mix the two styles under one service, because YAML will not
parse a block that is half list and half mapping.

Notes on three of these:

- `gotrue-config` is mounted read-only into `supabase-auth` and read-write into
  `supabase-studio`. Studio is the only writer.
- `GOTRUE_MAILER_TEMPLATE_RELOADING_ENABLED` and `GOTRUE_MAILER_TEMPLATE_MAX_AGE` make GoTrue
  re-fetch a template in the background rather than caching it for its default 10 minutes
  (`internal/conf/configuration.go:680,687`). Without them an edited email template keeps
  sending the old copy for up to ten minutes.
- `ENABLED_FEATURES_AUTHENTICATION_THIRD_PARTY_AUTH` turns off the Third-Party Auth page, which
  this fork does not support. The name is derived by
  `packages/common/enabled-features/overrides.ts` from the feature key
  `authentication:third_party_auth`: uppercase it, replace every non-alphanumeric character with
  `_`, and prefix `ENABLED_FEATURES_`.

`SUPABASE_PUBLIC_URL` is already in the stock Supabase compose's studio service, so it needs no
new line here.

## Verifying a deployment

**At boot**, `supabase-auth` logs that the watcher started:

```
starting configuration reloader
```

**After a save in the dashboard**, within about six seconds:

```
reloading api with new configuration
```

**When a value is rejected**, the old configuration stays live and nothing breaks:

```
reloader: error loading config
```

(The three strings are at `cmd/serve_cmd.go:118`, `cmd/serve_cmd.go:131` and
`internal/reloader/reloader.go:161` in the GoTrue source.)

**Read what Studio actually wrote:**

```bash
docker exec <auth-container> cat /etc/gotrue/99_studio.env
```

**Check that a bad value fails safe.** This is the one test worth running by hand, because the
whole design rests on a rejected reload leaving the running config alone. Write a line GoTrue
cannot parse into the file, from the Studio container (the auth container mounts it read-only):

```bash
docker exec <studio-container> sh -c "echo 'GOTRUE_JWT_EXP=\"\"' >> /etc/gotrue/99_studio.env"
```

`GOTRUE_JWT_EXP` is an integer field, and an empty value fails the parse for the whole directory.

Expected: `reloader: error loading config` in the auth log, and logging in still works on the old
configuration. To undo it, save anything in the dashboard — `99_studio.env` is rendered whole from
Studio's state and replaced by a rename, so the hand-added line is gone and the next log line is
`reloading api with new configuration`. Confirm with the `cat` above.

## Known limitations

- **Overview and Third-Party Auth are not supported.** Overview is behind the `authOverviewPage`
  feature flag, and no flag service answers self-hosted, so it stays hidden on its own.
  Third-Party Auth has to be turned off explicitly with the
  `ENABLED_FEATURES_AUTHENTICATION_THIRD_PARTY_AUTH=false` line above.
- **OAuth Server, OAuth Apps and custom OAuth providers are unverified.** Those pages talk to
  the project's own GoTrue admin API rather than to anything this fork wrote, and they need
  `OAUTH_SERVER_ENABLED` and `CUSTOM_OAUTH_ENABLED` set in the config. Whether
  `supabase/gotrue:v2.186.0` serves those admin endpoints has not been checked on a live stack.
  If the pages error, bump the auth image to the version the official compose pins,
  `supabase/gotrue:v2.196.0` (`docker/docker-compose.yml:111`), and Restart.
- **Turning a session limit back off needs a Restart.** GoTrue keys are sticky, so clearing
  `SESSIONS_TIMEBOX` or `SESSIONS_INACTIVITY_TIMEOUT` after enabling them does not unset the
  value in the running process. Restart `supabase-auth` after disabling either.
- **The UI wins over Coolify.** A value saved in the dashboard is written to `99_studio.env`,
  which overrides the same variable set in the compose file. Changing it in Coolify afterwards
  will look like it did nothing.
- **Clearing a value in the dashboard clears it for good, not back to Coolify.** Emptying a field
  the compose file also sets — turning SMTP off, say, while `GOTRUE_SMTP_HOST` is in the compose
  environment — records the clearing rather than forgetting the setting, and `99_studio.env`
  carries `GOTRUE_SMTP_HOST=""`. The compose value does not answer again. To bring it back, either
  set the value in the dashboard, or delete `auth-config.json` from the `studio-auth-state`
  volume, which discards every dashboard change at once.
- **OAuth callbacks need `SUPABASE_PUBLIC_URL` on the Studio container.** Without it Studio writes
  no `GOTRUE_EXTERNAL_<PROVIDER>_REDIRECT_URI` at all, and GoTrue refuses the sign-in with
  `missing redirect URI` unless the auth container's own environment supplies one. The stock
  Supabase compose already sets `SUPABASE_PUBLIC_URL`; a stripped-down compose may not.
- **SAML cannot be turned on from the dashboard.** GoTrue demands `GOTRUE_SAML_PRIVATE_KEY` the
  moment SAML is enabled (`internal/conf/saml.go:45`), and that is not a key in the config
  contract, so nothing the dashboard sends can supply one. Saving the toggle is refused with a
  message saying as much; writing it anyway would fail the reload and then crash-loop
  `supabase-auth` on its next restart. To run SAML, put the private key in the auth container's
  environment and enable it there.
- **Email template URLs set in Coolify stop applying after the first save.** The
  `GOTRUE_MAILER_TEMPLATES_*` variables are deliberately not mirrored — GoTrue holds a template as
  a URL and the dashboard holds it as a body, so there is nothing there to read one out of — and
  every template the dashboard has not customised is written as `=""`, which is how GoTrue is told
  to use its built-in copy. A template URL set in the compose file is therefore overridden by the
  first save from the dashboard. Manage templates from the dashboard instead.
- **The `MFA_ALLOW_LOW_AAL` toggle is stored but never applied.** The platform types it a boolean
  and GoTrue's `GOTRUE_SESSIONS_ALLOW_LOW_AAL` is a duration, so there is no honest translation
  from the one to the other. The switch round-trips in the UI and reaches no GoTrue field.
- **`SMS_TEST_OTP` and `SMS_TEST_OTP_VALID_UNTIL` cannot be cleared through the file.** GoTrue
  reads them as a map and a timestamp, and an empty value for either fails the whole reload, so
  clearing one drops the key instead of writing it — and a dropped key leaves the last value in
  force. Clearing a test OTP takes a Restart of `supabase-auth`.
- **Secrets sit in plain text in two Docker volumes.** SMTP passwords, OAuth client secrets and
  hook secrets are in `auth-config.json` (mode 0600) and in `99_studio.env` (mode 0644). A `GET`
  of the auth config also returns `SMTP_PASS` in clear text to any Studio user; the UI never
  renders it, but it is in the JSON.
- **The email-template content URL is unauthenticated by design.** GoTrue fetches it from inside
  the compose network with no credentials, so the handler runs without authentication. It serves
  only HTML that a dashboard admin authored. A template that was never customised is not served
  at all: the env file carries `GOTRUE_MAILER_TEMPLATES_<ID>=""` and GoTrue uses its built-in
  template without making a request. The endpoint's 404 is the fallback for the window in which
  GoTrue still holds the old URL — between a reset and the reload, or until a cached template
  ages out. Do not expose that path through Kong or any public proxy.
- **Only the Next build ships.** All five fork routes have TanStack mirrors and are registered in
  `routeTree.gen.ts`, but the publish workflow builds the Next target only. Nothing in CI builds
  or exercises the TanStack variant of these routes.
- **Two concurrent saves can lose one.** Each file is written atomically, but the
  read-modify-write of `auth-config.json` is not locked. Fine for one admin, not for several
  saving at once.

## Updating from upstream

Two remotes matter here, by role rather than by name. One points at `supabase/supabase`, whose
default branch is `master`; the other is your fork, `krowli/supabase`, which the publish workflow
runs from. In the original working clone the upstream repo was `origin` and there was no fork
remote at all. The convention once you have a fork is the other way round — `origin` is your
fork and the upstream repo is `upstream` — and that is what the commands below assume.

```bash
# One time, if the upstream remote does not exist yet.
git remote add upstream https://github.com/supabase/supabase.git

git fetch upstream master

# Rebase onto the upstream commit the weekly supabase/studio image was built from,
# not onto the tip of master.
git rebase <that-commit> fork/auth-selfhosted

npx -y pnpm@11.13.1 --filter studio test
npx -y pnpm@11.13.1 --filter studio typecheck

git push --force-with-lease origin fork/auth-selfhosted
```

Pushing the branch runs `.github/workflows/studio-fork-publish.yml`, which publishes
`ghcr.io/krowli/studio:latest` and a dated `YYYY.MM.DD-sha-<sha>` tag. Wait for it to go green,
then change the image tag in Coolify and redeploy.

The workflow pushes as `${{ github.actor }}` with the built-in `GITHUB_TOKEN`, so the fork repo
has to live under the `krowli` account for that image path to be writable. Under a different
owner, change `images:` in the workflow to match, or the push fails with a 403.

The workflow pins the framework, passing `STUDIO_FRAMEWORK=next` as a build-arg rather than
relying on the default in `apps/studio/Dockerfile`. Upstream owns that default, and this fork
builds and tests only the Next routes, so the pin is what stops a rebase from quietly switching
the published image to the TanStack build. Leave it in place unless you have also built and
exercised the TanStack variant of the five fork routes.

Two things to re-check after any rebase that touches auth:

- The four gate edits above are the ones most likely to conflict, since upstream owns those
  files.
- `apps/studio/routeTree.gen.ts` is generated. If it conflicts, take upstream's version and
  regenerate rather than merging by hand.
